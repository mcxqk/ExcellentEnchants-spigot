# ExcellentEnchants Luminol 26.2 适配设计

## 目标

基于 `nulli0n/ExcellentEnchants-spigot` 的 `master` 分支提交 `4bd372e5a73c5055d935d93c55ba7717393dd0e1`，将 ExcellentEnchants 5.4.3 适配到 Minecraft 26.2、Luminol 26.2 build 726 和 Java 25。交付只承诺 Luminol 26.2，不承诺 Paper、Spigot、其他 Folia 分支或其他 Minecraft 版本。

适配必须覆盖 Luminol 26.2 Paper Registry API、Folia 调度、区域所有权、共享状态、异步传送、任务和缓存生命周期，并通过自动化构建与本地 Luminol 26.2 启动冒烟测试。

## 范围

### 范围内

- 直接使用 `paper-plugin.yml` 声明的 `PaperEnchantsBootstrap` 和 Luminol 26.2 Paper Registry API 注册附魔、物品标签、战利品与交易标签。
- 从目标 Maven 反应堆和 Core 编译依赖中移除传统 Spigot/NMS 模块，并删除 Core 中仅供 Spigot 入口使用的实现。
- 根工程、Core 和参与交付的模块使用 Java 25 编译。
- Core 不依赖或打包传统 Spigot NMS 实现；旧版本源码目录可以保留用于追溯，但从目标 Maven 反应堆和 Core 依赖中移除。
- 增加项目级调度语义包装层，业务代码不直接调用传统 BukkitScheduler。
- 扫描并修复当前需求调用链中的并发集合、区域所有权、同步传送、阻塞等待和生命周期问题。
- 在 `plugin.yml` 和 `paper-plugin.yml` 中声明 Folia 加载能力，并在保留 NightExpress 的基础上追加作者 `cloudfl4re`。
- 使用 NightCore 2.16.4 的 26.2/Folia Server Bridge 作为首选平台抽象和运行依赖。
- 构建最终 ExcellentEnchants JAR，并在指定 Luminol build 726 上执行启动、加载、命令、禁用和日志冒烟测试。

### 范围外

- 不承诺 Paper、Spigot、其他 Folia 分支或其他 Minecraft 版本兼容。
- 不为传统 Spigot 新增 26.2 NMS 注册实现。
- 不修改 NightCore 仓库，除非后续证据证明它是阻断 ExcellentEnchants 在目标核心加载的根因；发生这种情况时先报告并请求扩大范围。
- 不为 ProtocolLib、PacketEvents、PlaceholderAPI 或 MythicMobs 本身提供 26.2/Folia 适配。
- 不重新设计附魔玩法、配置格式、命令节点、权限或公开 API。`reload` 节点保留，但在 Luminol 上返回必须完整重启的安全提示，不执行热重载。
- 不进行真实多玩家跨 Region 压力测试，不把单次启动冒烟测试解释为生产环境线程安全证明。
- 发现规则指定的不可用事件时只报告，不自行设计替代玩法。
- 源码修改不新增注释或 emoji；保留与当前需求无关的上游已有注释。

## 架构

工程继续使用现有 Maven 多模块边界：

```text
ExcellentEnchants
├─ API
├─ Core
│  ├─ 业务逻辑
│  ├─ 事件、命令和管理器
│  ├─ PaperEnchantsBootstrap
│  └─ SchedulerUtil 调度语义边界
├─ tooltip-packetevents
├─ tooltip-protocollib
└─ compat-mythicmobs
```

根 Maven 反应堆只保留 API、Core 和可选集成模块，移除全部旧 NMS 模块条目。Core 删除旧 NMS 依赖、`SpigotEnchantsBootstrap` 和 `SpigotItemTagLookup`，只保留 `PaperEnchantsBootstrap` 版本入口。旧源码目录保留用于追溯，但不参与目标反应堆。最终 shaded JAR 仍由 Core 生成，插件名称、主类和版本保持现有值。

该修正基于克隆后的实际启动链：Luminol 读取 `paper-plugin.yml`，由 `PaperEnchantsBootstrap` 在 Paper 生命周期中注册附魔；`EnchantsPlugin` 仅在 `Version.isSpigot()` 为真时调用 `SpigotEnchantsBootstrap`。Luminol 由 NightCore 识别为 Paper/Folia，因此传统 Spigot NMS 入口不会运行。目标核心的实际启动链优先于设计前对 NMS 模块的假设。

`PaperEnchantsBootstrap` 根据本地 Luminol API 逐项编译和验证。任何与 26.1.2 不同的 Paper Registry、生命周期、标签或附魔构建接口都以 build 726 的实际 API 为准，并记录差异。

## 平台检测与调度

插件在 `onEnable` 的最早可用阶段初始化平台状态并只检测一次 Folia/Luminol。检测结果存入静态缓存，后续代码只读取缓存。唯一允许的反射用途是这次检测；调度不使用反射。

交付目标只有 Luminol 26.2，但调度包装层仍保留规则要求的内部非 Folia 回退。该回退不接受单独兼容测试，也不构成对 Paper 或 Spigot 的支持承诺。

包装层优先委托 NightCore 的 Folia Server Bridge。NightCore 缺少某项明确语义时，包装层直接调用 Luminol/Paper 官方 API。业务代码只能调用包装层，不能直接调用 `Bukkit.getScheduler()`。

包装层提供以下职责：

- 实体所有者上下文执行。
- 实体所有者上下文延迟执行，延迟强制不低于 1 tick。
- Location 或 Chunk 所属 Region 执行。
- Region 延迟执行，延迟强制不低于 1 tick。
- Global 上下文执行。
- 不接触 Bukkit 活状态的异步执行。
- `teleportAsync` 统一传送并传播完成或失败状态。
- 使用 `Bukkit.isOwnedByCurrentRegion` 判断 Luminol 所有权；非 Folia 回退才使用 `Bukkit.isPrimaryThread`。

如果调用者已经位于正确所有者上下文，允许在当前 tick 直接完成逻辑。跨上下文调用必须经过调度器，并接受至少 1 tick 延迟。禁止使用反射、同步 Future 等待或其他方式绕过该延迟。

## 预修改审计

修改源码前，对每个问题点记录：

- 事件、命令、任务或回调入口。
- 从入口到最终 Bukkit、Paper 或 NMS 操作的完整调用链。
- 当前线程或调度上下文。
- Player、Entity、Location、Chunk、World、Block 或 Inventory 的真实所有者。
- 跨边界传递的是活对象、UUID、不可变快照、坐标副本还是普通值。
- 任务、缓存、Future、监听器和外部资源的终止与清理位置。
- 命中的 Folia 规则。
- `must_fix`、`suggested_fix`、`defer` 或 `uncertain` 分级。

当前需求调用链中的硬规则违反项必须修复。无关问题只记录为 `defer`，不扩大重构范围。缺少源码、构建、日志或第三方契约时标记为 `uncertain`。

## 区域所有权与数据流

Player、Entity、World、Chunk、Block 和 Inventory 等活状态只能在其所有者上下文访问。异步线程、Global 上下文和其他 Region 不读取或写入这些对象。

跨边界流程固定为：

1. 在 Entity 或 Region 所有者上下文读取状态。
2. 创建 UUID、坐标副本、物品副本、数值和字符串组成的不可变快照。
3. 将快照交给异步计算或 IO，不携带可变 Bukkit 活状态。
4. 使用实体或 Region 调度回所有者上下文。
5. 写回前验证插件仍启用、目标仍有效、玩家仍在线且业务状态未过期。
6. 完成写回并清理 Future、任务句柄和临时引用。

Inventory、装备、掉落物生成和实体生成必须在实体或区域所有者上下文执行。读取、消耗、发放、生成和清理必须有单次执行保证，避免物品或实体复制。

传送统一使用 `teleportAsync`。完成回调不得同步等待其他 Region、数据库、网络或文件结果；需要访问目标区域状态时再次通过实体或目标 Region 调度并验证所有权。

## 共享状态与并发集合

扫描静态字段、单例 Manager、缓存、会话表、玩家表、去重集合、任务表和 in-flight Future。

- 跨 Region 的 `HashMap` 使用 `ConcurrentHashMap`。
- 跨 Region 的 `HashSet` 使用 `ConcurrentHashMap.newKeySet()` 或适合读多写少场景的 `CopyOnWriteArraySet`。
- 读多写少的共享列表使用 `CopyOnWriteArrayList`。
- 写多的共享列表使用同步列表，并在迭代期间进行外部同步。
- 复合读改写使用 `compute`、`merge`、原子变量或窄范围锁，不因容器线程安全而忽略业务原子性。
- 仅在启用阶段构造并在运行期只读的数据转换为不可变集合。
- 迭代使用弱一致性并发迭代器或不可变快照。
- 缓存必须有容量限制、过期策略或明确移除路径。

静态或全局结构不长期持有 Player、Entity、World、Inventory 或插件实例。玩家离线、实体失效、功能重载和插件禁用时移除关联状态。

## 不可用事件

扫描以下事件：

- `PlayerRespawnEvent`
- `PlayerTeleportEvent`
- `PlayerChangedWorldEvent`
- `WorldLoadEvent`
- `WorldUnloadEvent`

如果源码存在监听器，报告必须列出类名、监听方法和事件名，并声明目标 Luminol 26.2 的 Folia 层无可调用 API。没有用户新增授权时不提供或实现替代方案。

如果本地 build 726 核心与上述规则产生可验证冲突，以核心实际行为作为编码依据，同时在报告中列出规则预期、核心证据和最终采用方式。

## 生命周期和故障处理

所有延迟和重复任务登记到线程安全任务集合。任务自然结束、自行取消或异常结束时移除句柄。异步操作登记到有清理路径的 in-flight 集合，并在 `whenComplete` 中移除。

每个回调写回前检查生命周期状态和目标有效性。插件禁用或重载后，旧回调不能修改新状态。

`onDisable` 按以下顺序处理：

1. 标记停止接收新任务。
2. 取消已登记任务。
3. 阻止异步结果继续写回。
4. 注销监听器。
5. 关闭发现的执行器、HTTP 客户端或其他外部资源。
6. 清空缓存、Future 表和全局引用。

Region 回调不执行数据库、网络或文件 IO，不调用 `Future.get()` 或 `join()`，不等待另一个 Region。异常通过异步完成链传播，并在正确所有者上下文处理玩家可见结果。

Luminol 上不执行 NightCore 的 Manager 热重载。原因是 Global 发起的 Manager 重建无法证明所有 Region 中已开始的事件回调全部终止；`reload` 命令保留并提示使用完整服务端重启。这样不存在旧 Manager、旧监听器或旧任务在新状态建立后继续写回的重载路径。

投射物命中、伤害和死亡事件如果引用远程 shooter 或 killer，只有当前 Region 同时拥有该实体时才执行需要同时访问两端活状态的附魔效果。所有权不满足时跳过该双实体效果，不取消原事件，也不跨 Region 重放必须在当前 tick 完成的事件。

## 测试策略

### 自动化测试

对能够从 Bukkit 静态状态中隔离的逻辑执行测试驱动开发：

- Folia 检测只初始化一次。
- Entity 和 Region 延迟最小值为 1 tick。
- 已处于所有者上下文时的直接执行路径。
- 跨上下文调度路径选择。
- 任务和 Future 完成后的登记移除。
- 插件禁用后回调不再写回。
- 并发状态的原子更新与清理。

每项行为先建立失败测试，再做最小实现。难以在单元测试进程中加载的 Paper Bootstrap 代码使用编译、API 签名核对和服务端集成启动验证。

### 静态红线扫描

构建前后都扫描：

- 业务代码中的直接 `Bukkit.getScheduler()`。
- 同步 `teleport(...)`。
- Entity 或 Region 延迟低于 1 tick。
- Region 回调中的 `Future.get()`、`join()` 或阻塞 IO。
- 异步线程或错误 Region 对 Bukkit 活状态的访问。
- 共享普通可变集合。
- 五种指定不可用事件。
- 没有取消或清理路径的任务、缓存、Future、监听器和资源。

### 构建

系统没有 Maven，因此通过 `http://localhost:7897` 下载临时 Maven。构建使用 Java 25、临时代理配置和隔离的 Maven 本地仓库。Luminol API 优先使用本地 build 726 JAR，避免远端版本漂移。

执行完整 Maven 测试和打包，检查退出码、测试失败数、shade 结果、插件描述文件和最终 JAR 内容。构建完成后删除临时 Maven、临时代理配置和不需要交付的缓存。

### Luminol 26.2 启动冒烟测试

在隔离临时目录中复制指定 paperclip，安装官方 NightCore 2.16.4 和本次构建的 ExcellentEnchants。测试实例绑定回环地址和临时端口，禁用 RCON 与 Query，使用离线测试配置并接受该临时实例的 EULA。

启动后验证：

- Luminol 完成启动。
- NightCore 成功加载。
- ExcellentEnchants 成功加载且没有自禁用。
- Paper 26.2 Bootstrap 被正确执行。
- 附魔注册完成。
- 插件控制台命令可执行。
- 日志没有 `ERROR`、`SEVERE`、线程检查、区域所有权、缺类、缺方法、注册表或生命周期异常。

通过控制台正常停止服务端，验证禁用阶段没有遗留回调和关闭异常。保留必要日志证据，清理临时世界、运行依赖、缓存和服务端目录。
